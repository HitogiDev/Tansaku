# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Tansaku is the marketing/landing website for an anime-merch shop in San Pedro de Macorís, Dominican Republic. It's a single-page Astro site, in Spanish, that sells posters (11x17: 1 por RD$100 · 2 por RD$180 · 3 por RD$250) and stickers (RD$10) via WhatsApp ordering links, plus a product catalog page. Physical manga is coming soon: the landing page previews it ("próximamente") and collects WhatsApp/email requests through a Formspree form so people can ask for the series they want.

## Commands

```sh
npm install       # install dependencies
npm run dev       # dev server at localhost:4321
npm run build     # production build to ./dist/
npm run preview   # preview the production build locally
npm run dev:admin     # admin panel dev server at localhost:4322
npm run build:admin   # admin panel production build to ./dist-admin/
npm run astro ... # run Astro CLI commands (e.g. `npm run astro check`)
```

There is no test suite and no lint script configured. `npm run astro check` is the closest thing to a correctness check (type/template checking via `astro/tsconfigs/strict`).

Node >= 22.12.0 is required (see `engines` in `package.json`).

## Architecture

- **Astro 6** (static output) + **Tailwind CSS v4**, wired in via the `@tailwindcss/vite` plugin in `astro.config.mjs` (not the older Astro Tailwind integration). `src/styles/global.css` is just `@import "tailwindcss";`.
- **The landing page is one file: `src/pages/index.astro`.** It's a full standalone HTML document (own `<html>`/`<head>`/`<body>`, not composed from a layout) containing every section — sticky nav (horizontal logo), hero (fanned manga covers + stickers, no prices — prices live in the merch cards and the catalog), ticker, merch (with a "cómo comprar" steps strip), manga preview ("próximamente"), about, FAQ (`<details>` accordions, no JS), "pide tu serie" form — plus a floating WhatsApp button, a large `<style is:global>` block (most of the file) and an inline `<script is:inline>` at the bottom for the dark/light theme toggle, the manga-cover shuffle, form prefill and scroll reveals. Repeated content (merch cards, steps, icons, ticker items) is defined as data in the frontmatter. The FAQ is duplicated in a JSON-LD block in `<head>` — keep both in sync.
- **Brand guide (Guía de marca v2) governs copy, colours, fonts and logo.** Copy rules: only what's in stock today (posters, stickers); pines are "próximamente" with no date or price; manga is announced as "próximamente" (the owner's call, overriding the guide); figures and clothing must not be implied; payment is cash or transfer only (no card); free delivery is *only* in San Pedro de Macorís; no invented stats, reviews or scarcity; tuteo; one exclamation mark. Price in RD$ and "pagas al recibir" always visible. Palette: Rojo Tansaku `#DC2626` (fills/large headlines; use `--red-text` = Rojo claro `#EF4444` for red text on dark), Amarillo `#FFD23F`, Menta `#5EEAD4` (`--cyan`), Noche `#0B1118` (dark bg), Tinta `#0D0D0F` (`--ink`), Crema `#FFF6E5`, Humo `#CBD5E1` (muted). Text on yellow/mint is always Tinta. Logo files live in `src/assets/logos/` (not `brand/` — that folder name is gitignored): the logo appears only in the navbar, as the horizontal logo (`horizontal-claro.png` in dark theme, `horizontal.png` in light), unmodified — no rotation, borders, shadows or effects, min 110px wide, clear space of half the seal's diameter around it.
- **Visual language ("manga magazine cover").** Design tokens are CSS variables at the top of the `<style>` block in `index.astro` (`--bg`, `--surface`, `--text`, `--stroke`, `--red`, `--red-text`, `--yellow`, `--cyan`, `--shadow`, …), switched by `data-theme` (dark is the default). The look is: Noche / Crema backgrounds, red + yellow accents, 2px borders with hard offset shadows (no blur, no rounded corners), halftone dot and speed-line backgrounds, tilted "sticker" labels and katakana accents. Fonts (guide §05): `Bebas Neue` (`--font-display`, headlines, uppercase, +0.05em), `Dela Gothic One` (`--font-fun`, stickers, numbers/prices, Japanese), `Inter` (`--font-body` and `--font-label`, labels in 800 uppercase +0.14em), `Noto Sans JP` (`--font-jp`, background kanji watermarks). Styles are mobile-first with `min-width` breakpoints at 480/640/900/1200px. `catalogo.astro` duplicates the same tokens, buttons, nav and footer styles — keep the two in sync.
- **`src/layouts/Layout.astro` and `src/components/Welcome.astro` are unused leftovers from `astro create`'s starter template.** Nothing imports them. Don't wire new pages through `Layout.astro` without checking whether `index.astro`'s inline document structure should be reused instead — the two approaches aren't currently consistent.
- **Manga preview images are data-driven from the filesystem.** Drop a cover into `src/assets/covers/` (`jpg`/`jpeg`/`png`/`webp`/`avif`) and `import.meta.glob` in `index.astro` picks it up for the hero fan and the manga rail. Title and genre come from `mangaMetaBySlug` (keyed by lowercased filename without extension); unknown slugs fall back to a title-cased slug and "Manga / Interés". The rail client-side shuffles and shows a random 6 on each load.
- **Product catalog + admin panel (Supabase).** See `ADMIN.md` for setup. `src/pages/catalogo.astro` (`/catalogo/`) is a standalone page (own `<html>`, own `<style is:global>` with the same token names as `index.astro`, switched by `data-theme`, same `tansaku-theme` localStorage key) that fetches published rows from the Supabase `products` table client-side and filters/sorts them in the browser (category chips, price range, search, sort, in-stock), syncing filters to the query string. On mobile the search + category chips are a sticky toolbar and the rest of the filters live in a bottom sheet (`#filters-panel`); from 900px up they become a sticky sidebar. Skeleton cards show while loading. Clicking a card opens a native `<dialog>` (bottom sheet on mobile, two-column panel on desktop) with a scroll-snap photo gallery. To preview it with data without a real project, build with dummy `PUBLIC_SUPABASE_*` values and intercept `rest/v1/products` and `storage/` requests in Playwright. The admin panel is a **separate Astro build**: `astro.config.admin.mjs` sets `srcDir: ./admin/src`, `publicDir: ./admin/public`, `outDir: ./dist-admin`; it's meant to be deployed on its own host (Cloudflare Pages) at `admin.tansaku.site`, since GitHub Pages allows one domain per repo. It does email/password login, then checks the `is_admin()` RPC; products can have up to `MAX_PHOTOS` (10) photos stored in `image_paths text[]` (first = cover, mirrored into the legacy `image_path` column; read them via `productImages()`); photos are resized/compressed to WebP in the browser and uploaded to the public `product-images` storage bucket. Shared code (client, types, price/WhatsApp helpers, `DEFAULT_CATEGORIES`) is in `src/lib/shop.ts`. Schema changes go in `supabase/schema.sql` (kept idempotent) plus a numbered file in `supabase/migrations/` for projects that already ran it. All write security lives in Row Level Security in `supabase/schema.sql` (only users in `public.admins` can write) — the anon key in the bundle is public by design. Config comes from `PUBLIC_SUPABASE_URL` / `PUBLIC_SUPABASE_ANON_KEY` (`.env` locally, repo Actions *variables* in CI); without them both pages build fine and show a "not configured" fallback. Product data is rendered with `textContent`/DOM APIs, never `innerHTML`.
- **WhatsApp is the checkout mechanism.** Merch "buy" buttons and the contact CTA are `wa.me/8098795559?text=...` links with pre-filled messages, not an actual cart/checkout flow. There's no backend.
- **The signup form posts to Formspree** (`https://formspree.io/f/xkoqvawb`) via plain HTML form POST — no client-side handling.
- **Theme toggle** is persisted to `localStorage` under the key `tansaku-theme` and applied via a `data-theme` attribute on `<html>`, set by the inline script (runs before hydration concerns apply since there's no framework runtime involved — this is a static/vanilla-JS site, no React/Vue/etc.).

## Deployment

- GitHub Actions (`.github/workflows/deploy.yml`) builds and deploys to **GitHub Pages** on every push to `main` or `master`, or via manual dispatch. It runs `npm ci && npm run build` (with the Supabase vars from repo Actions variables) and publishes `./dist`. The admin panel is *not* deployed by this workflow — it's built by Cloudflare Pages with `npm run build:admin` → `dist-admin` (see `ADMIN.md`).
- Custom domain is `tansaku.site`, configured via `public/CNAME` and `site` in `astro.config.mjs` — keep these in sync if the domain ever changes.
